NMEA and UBX Protocol Reference

A practical protocol reference for the GPS Lab project. It covers the NMEA text protocol and the UBX binary protocol, with emphasis on u-blox 6 / NEO-6M and on the messages actually used by this project.

Important: NMEA is a family of compatible sentence formats, while UBX capabilities depend on the u-blox firmware generation. A message found in a newer protocol manual is not automatically supported by an older NEO-6M receiver.

This reference does not replace the official manufacturer protocol specification. It is intended as an engineering map for reading traces, sending manual polls, and troubleshooting receivers.

NMEA and UBX — the key difference

NMEAASCII sentences starting with $, normally ending with *HH\r\n. Human-readable.
UBXBinary u-blox frames using sync bytes B5 62, class/id, payload length, payload, and CK_A/CK_B.
Mixed streamA u-blox receiver can accept and transmit NMEA and UBX on the same interface; both formats may be interleaved.
Typical useNMEA is mainly navigation output. UBX adds advanced navigation data, monitoring, configuration, and service functions.

UART and mixed stream

For NEO-6M, a typical factory UART1 configuration is 9600 8N1. NMEA and UBX are normally accepted on the same input without a separate protocol switch. Default output contains standard NMEA sentences; UBX messages may be enabled by configuration or returned in response to poll requests.

In GPS Lab, the preferred workflow is to discover the baud rate from valid NMEA first, then use read-only UBX polls for identification and engineering diagnostics.

NMEA framing

$GPGGA,hhmmss.ss,....*CS\r\n
ElementDescription
$Start of sentence.
GPTalker ID — navigation source/family.
GGAMessage type.
,...Comma-separated ASCII fields; empty fields are valid.
*CSTwo hexadecimal digits containing the XOR checksum.
CR LFLine terminator: bytes 0D 0A.

NMEA checksum

XOR all ASCII bytes between $ and *, excluding the $ and * characters themselves.

value = 0
for ch in body:
    value ^= ord(ch)

A parser should primarily identify the last three characters of the sentence type — GGA, RMC, GSA, etc. — and keep the talker prefix as a separate value.

Coordinates, time, and date

Coordinates

NMEA normally encodes latitude as ddmm.mmmm and longitude as dddmm.mmmm. Convert with:

decimal = degrees + minutes / 60
S or W => negative value

Example: 5540.1234,N → 55° + 40.1234/60.

UTC

Time is normally encoded as hhmmss.sss. RMC date uses ddmmyy. Do not couple time availability to navigation fix validity: a receiver may provide correct GNSS UTC while position status is still NO FIX.

TXT — Text Transmission

Receiver service/status text. Typical structure:

FieldMeaning
TotalTotal number of parts.

On compatible receivers, TXT may report antenna state or software version. Always interpret the text in the context of the specific receiver manufacturer and firmware.

UBX — binary frame structure

B5 62 | CLASS | ID | LEN_L LEN_H | PAYLOAD... | CK_A CK_B
OffsetSizeFieldDescription
01SYNC1B5
11SYNC262
21CLASSMessage class.
31IDMessage ID within the class.
42LENGTHLittle-endian payload length.
6NPAYLOADMay be zero-length for some poll requests.
6+N2CK_A/CK_BChecksum over CLASS through PAYLOAD.

UBX checksum

Two 8-bit accumulators. The sync bytes B5 62 are not included.

CK_A = 0
CK_B = 0
for byte in CLASS + ID + LENGTH + PAYLOAD:
    CK_A = (CK_A + byte) & 0xFF
    CK_B = (CK_B + CK_A) & 0xFF

ACK-ACK and ACK-NAK

MessageClass/IDPayload
ACK-NAK05 00Class + ID of the rejected message.
ACK-ACK05 01Class + ID of the accepted message.

A NAK means that a particular command was rejected. It does not automatically prove that the entire UBX protocol is absent. Some compatible or clone receivers recognize UBX framing yet reject unsupported commands with NAK.

CFG-RINV and non-volatile storage

UBX-CFG-RINV provides Remote Inventory storage. GPS Lab used this field for an open technological marker on genuine u-blox 6 receivers.

  • payload: flags + up to 30 bytes of inventory data;
  • read-back is performed with a subsequent poll;
  • for non-volatile persistence, GPS Lab sends CFG-CFG with the RINV configuration-group mask and the selected NVM device;
  • available EEPROM/Flash targets and supported deviceMask bits depend on the hardware configuration.
Do not confuse RINV with a cryptographic UID. It is a user inventory field and can potentially be copied.

A zero-length payload is not a valid poll form for every UBX message. Always verify the poll/set form in the protocol specification for the specific receiver generation.

Practical diagnostic workflow

  1. Are bytes arriving? If not, check power, common ground, TX/RX wiring, COM port, and baud rate.
  2. Is there a valid NMEA checksum? If yes, UART transport and the text protocol are already confirmed.
  3. Is GNSS UTC available? Treat it as an independent result; do not hide it because of NO FIX.
  4. Is there a position fix? Check GGA quality, RMC status, and GSA fix type.
  5. How many satellites? GSV shows satellites in view; GSA/GGA show satellites used.
  6. Is it a genuine u-blox receiver? Send MON-VER. A valid protocol response is stronger evidence than a board label.
  7. Engineering state: use MON-HW, MON-IO, RXBUF, and TXBUF.
  8. Must a setting survive power removal? After saving, always perform a full power-cycle and verify again.
