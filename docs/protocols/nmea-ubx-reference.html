Справочник протоколов NMEA и UBX

Практический справочник для лаборатории GPS Lab. Он описывает текстовый протокол NMEA и бинарный протокол UBX с акцентом на u-blox 6 / NEO-6M и на команды, реально используемые проектом.

Важно: NMEA является семейством совместимых форматов, а UBX зависит от поколения прошивки u-blox. Наличие класса или сообщения в более новой документации не означает его поддержку старым NEO-6M.

Справочник не заменяет официальную спецификацию производителя; он предназначен как инженерная карта для чтения трасс, ручной отправки запросов и диагностики.

NMEA и UBX — главное различие

NMEAASCII-строки, начинаются с $, обычно заканчиваются *HH\r\n. Хорошо читаются человеком.
UBXБинарные кадры u-blox, синхронизация B5 62, class/id, длина, payload, CK_A/CK_B.
Совместный потокu-blox может принимать и передавать NMEA и UBX на одном интерфейсе; кадры могут идти вперемешку.
НазначениеNMEA — навигационный вывод. UBX — расширенная навигация, мониторинг, конфигурация и служебные функции.

UART и совместный поток

Для NEO-6M типовая заводская настройка UART1 — 9600 8N1. На вход обычно принимаются NMEA и UBX без отдельного переключения. Выход по умолчанию содержит стандартные NMEA-сообщения; UBX-сообщения могут быть включены конфигурацией или отправлены как ответы на poll-запросы.

В GPS Lab правильная стратегия: сначала найти скорость по валидным NMEA, затем использовать read-only UBX polls для идентификации и инженерной диагностики.

Формат NMEA

$GPGGA,hhmmss.ss,....*CS\r\n
ЭлементОписание
$Начало предложения.
GPTalker ID — источник/семейство навигации.
GGAТип сообщения.
,...Поля ASCII, разделённые запятыми; пустое поле допустимо.
*CSДва шестнадцатеричных символа XOR checksum.
CR LFКонец строки: байты 0D 0A.

NMEA checksum

XOR всех ASCII-байтов между $ и *, не включая сами символы $ и *.

value = 0
for ch in body:
    value ^= ord(ch)

Координаты, время и дата

Координаты

NMEA обычно передаёт широту как ddmm.mmmm, долготу как dddmm.mmmm. Перевод:

decimal = degrees + minutes / 60
S или W => отрицательное значение

Пример: 5540.1234,N → 55° + 40.1234/60.

UTC

Время обычно имеет вид hhmmss.sss. Дата RMC — ddmmyy. Получение времени не надо смешивать с валидностью position fix: приёмник может выдавать корректное GNSS UTC при NO FIX.

UBX checksum

Два 8-битных накопителя. Синхробайты B5 62 в расчёт не входят.

CK_A = 0
CK_B = 0
for byte in CLASS + ID + LENGTH + PAYLOAD:
    CK_A = (CK_A + byte) & 0xFF
    CK_B = (CK_B + CK_A) & 0xFF

ACK-ACK и ACK-NAK

СообщениеClass/IDPayload
ACK-NAK05 00Class + ID отвергнутого сообщения.
ACK-ACK05 01Class + ID принятого сообщения.

NAK означает, что конкретная команда отвергнута. Это не доказывает автоматически отсутствие всего UBX-протокола. Некоторые совместимые/клоновые приёмники распознают UBX framing и NAK'ают неподдерживаемые команды.

CFG-RINV и сохранение конфигурации

UBX-CFG-RINV используется как Remote Inventory. В проекте GPS Lab он применялся для открытого технологического маркера на настоящем u-blox 6.

  • payload: flags + до 30 байт inventory;
  • read-back выполняется повторным poll;
  • для энергонезависимого сохранения GPS Lab использует CFG-CFG с маской группы RINV и выбранным NVM device;
  • наличие EEPROM/Flash и поддерживаемые deviceMask зависят от аппаратной конфигурации.
Не смешивать RINV с криптографическим UID. Это пользовательское inventory-поле и потенциально копируемая информация.

Практическая диагностическая логика

  1. Есть байты? Если нет — питание, земля, TX/RX, COM-порт, скорость.
  2. Есть валидный NMEA checksum? Если да — UART и текстовый протокол уже подтверждены.
  3. Есть GNSS UTC? Считать его самостоятельным результатом; не скрывать из-за NO FIX.
  4. Есть координатный fix? Проверить GGA quality, RMC status, GSA fix type.
  5. Сколько спутников? GSV = видимые, GSA/GGA = используемые.
  6. Это настоящий u-blox? Отправить MON-VER. Валидный ответ сильнее надписи на плате.
  7. Инженерное состояние u-blox: MON-HW, MON-IO, RXBUF/TXBUF.
  8. Конфигурация должна пережить питание? После save обязательно power-cycle и повторная проверка.
